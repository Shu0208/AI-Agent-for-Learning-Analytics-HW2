## 完整示例：成績統計 S03

1. **使用者輸入**：英文題目、規準與 S03。正式測試 T02 為空輸入，規格要求輸出 `0 0.00 0`。
2. **第一次決策與工具呼叫**：系統執行 `run_official`，逐案建立隔離容器。觀察到九案通過、T02 發生執行錯誤，功能分為 9 × 6。
3. **模型決策**：模型選擇 `inspect_T02`。程式把此動作轉成 `inspect_case("T02")`，取回實際輸入、預期結果及 traceback。第 6 行 `mean = sum(scores) / count` 在 count 為 0 時觸發除零例外。
4. **最終決策**：模型選擇評分。功能 54、邏輯 19、規格 9、可讀性 3，加總 85。報告將驗證事實與建議分項分開，並提示先處理分母為零的情況。
5. **追蹤方式**：JSON 的 `trace` 陣列依時序包含使用者輸入、決策、工具與觀察。最終結果見 `result`，逐案執行事實另列於 `test_results`。

## Agent 失敗情境與處置

| 情境 | 失敗原因與可觀察結果 | 處置與重現方式 |
|---|---|---|
| 模型服務不可用 | 將端點指向應用容器中無服務的連接埠，實際收到 connection refused；模型分析未完成。 | 紀錄 `pending` 與客觀功能分。恢復服務後重新執行同一份作業。`python3 grade.py --sample S03 --ollama-url http://127.0.0.1:1` |
| 補查額度耗盡 | 將上限設為 0，正式測試已觀察到失敗，但流程仍缺少詳細失敗證據。 | 紀錄 `needs_review`，保存失敗測試交由教師檢視。用預設額度重跑可取得 T02。`python3 grade.py --sample S03 --max-checks 0` |
| 模型理由不足 | 繁中單字題中，模型僅以 L6、L4、L5 等行號回答評分理由，並給出與同票問題無關的修改建議。 | 保存模型草稿與實測差異供複核，省略建議總分。`python3 grade.py --lang zh-Hant --task 03_words --sample S02` |

## 結果限制

- 端到端結果覆蓋三個題目及兩個語言版本。本次無全資料集的 Agent 準確率估計。資料集中 90 個檔案的學生程式行為驗證與本次七筆模型驗收屬不同實驗。
- 中英文成績統計 S03 的客觀分一致，建議總分相差 12 分。繁中模型理由部分偏離規準；另有全案通過的程式被建議使用其他資料結構。主觀分項仍需人工檢查，單組配對不足以推論語言表現。
- 實測錯誤、引用行號及模型推論有不同來源。Python 例外優先採 traceback 行號；其他情況的行號由模型提出。全案通過、除零與逾時的學生回饋採執行狀態對應的文字，供其他輸出不符案例使用的模型建議仍可能誤判。
- 本次端到端紀錄有呼叫 `inspect_case` 的決策。選擇性工具 `run_probe` 另在 Podman 整合測試中實跑 D01，並驗證重複 ID 與未知 ID 的拒絕行為。七筆紀錄未出現模型主動選擇補測的情況。
