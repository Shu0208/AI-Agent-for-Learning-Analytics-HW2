# Python 批改 Agent 雙語測試資料

本資料集有三題，每題 15 份自製的 Python 作業樣本。每份有英文與繁體中文兩個版本，合計 45 組配對、90 份單檔作業。兩版使用相同的程式邏輯、識別碼、輸入及指定輸出，題目、規準、程式註解及教師診斷則各自使用對應語言。英文操作說明見 [README.en.md](README.en.md)。

| 資料夾 | 題目 | 適合觀察的能力 |
|---|---|---|
| 01_scores | 成績統計 | 空資料、及格門檻、重複分數、輸出精度 |
| 02_parking | 停車費試算 | 無條件進位、累進費率、封頂及逾時 |
| 03_words | 找出最常見的單字 | 分詞、大小寫、同頻排序與空輸入 |

## 如何開始

1. 從 `en/01_scores/` 開始。給 Agent `assignment.md`、`rubric.json` 和一份 `submissions/Sxx.py`。這些程式全是合成的練習樣本。
2. 測試工具讀 `official_tests.json`。每個案例各開一次學生程式，把 `stdin` 原樣送入，收集標準輸出、錯誤和結束狀態。若學生程式正常結束，比對 `expected_stdout`。比對時統一換行格式，雙方各可忽略一個結尾換行；其他空白、大小寫與欄位順序均須一致。逾時從直譯器啟動時計，資料集驗證採每例 1 秒；使用容器時應另外計入容器啟動時間。
3. 每題 10 個正式案例，每案 6 分，合計功能分 60。另有 3 個診斷用補測在 `diagnostic_tests.json`，只用來釐清原因。邏輯 25 分、規格 10 分、可讀性 5 分由評閱者依程式證據判斷。
4. Agent 完成後，再開 `teacher_only/zh-Hant/` 或 `teacher_only/en/`，按題目及樣本編號核對客觀分數、各案實際狀態、輸出或例外，以及診斷重點。盲測時，將教師答案放在 Agent 可讀範圍之外。`reference.py` 可供教師檢查測試環境。
5. 比較語言時，使用同題、同編號、相同規準和模型設定，另開一次對話並改用另一語言。觀察工具選擇、分數及評語是否有證據。45 組配對各代表一個獨立樣本。

## 第一個展示

先試英文版 `01_scores/S03`（檔案在 submissions 內）。第一次用 80、70、90 三個分數可以算出平均；第二次給空輸入，檢查工具回傳的例外。請 Agent 指出哪個運算在空資料時失敗，並引用證據給一項修正建議。然後對繁中版同編號重做一次。兩次請各自保存決策追蹤。

在有 Python 測試映像的 Podman 環境中，可從本 README 所在資料夾重跑正常輸入。第一次使用會下載映像。

```sh
printf '80 70 90\n' | podman run --rm -i --network=none --read-only \
  --memory=128m --pids-limit=32 \
  -v "$PWD/en/01_scores/submissions/S03.py:/submission.py:ro" \
  docker.io/library/python:3.12-slim python -I -B /submission.py
```

預期輸出為 `3 80.00 3`。把 `printf '80 70 90\n'` 改成 `printf ''` 可以重現空輸入。停車題包含故意不會結束的學生迴圈，批次測試時請用能逾時終止程序／容器的執行工具。

## 驗證範圍

本包已用 Python 3.12 執行所有 90 份樣本，每份 10 個正式案例和 3 個補測，共 1,170 次；另以兩個語言目錄的參考解各跑過所屬題目的 13 個案例。教師資料中的測試狀態來自上述執行，診斷文字是針對已知解法編寫的參考說明。這份驗證涵蓋學生程式的行為。要驗收 Agent 本身，可另測模型服務不可用、補查達上限等狀況，並保存實際追蹤。
